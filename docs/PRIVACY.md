# 隐私与脱敏规则（Privacy Rules）

> **这一页是硬约束，不是建议。** 本项目是公开发布的 npm 包 + GitHub 仓库，
> 凡是进了仓库的东西，用户装一次包就落到他的磁盘上，也永远留在 git 历史与
> npm 的每一份 tarball 里。**发出去就收不回来。**
>
> 早期版本的截图里用过真实数据，已经在 1.19.2 统一换成假值。
> 这份文档是那次教训的产物。

## 0. 一条判据

> **假设这段文字 / 这张图明天会被贴到 issue 里、被搜索引擎索引、被不认识你的人读到。
> 你愿不愿意让别人知道它对应的是你本人、你的钱包、你的这台机器？**

不愿意的，就不能进仓库。没有「反正只是个昵称」这一档——昵称 + 余额 + 到期时刻
拼起来足以定位一个真实账户。

## 1. 绝对禁止进入仓库的内容

| 类别 | 具体形态 | 为什么 |
| --- | --- | --- |
| 凭据 | PAT（`pt-…`）、`access_token` / `refresh_token` / `security_oauth_token`、jobToken、npm `_authToken`、`ghp_…`、私钥 | 直接就是账户控制权 |
| 凭据指纹 | `pat-<sha256 前 16 位>` 形式的账号 id | 能确认「这把钥匙对应这个人」，且能跨仓库串起来 |
| 真实账号标识 | 邮箱、手机号、上游昵称（形如 `nick1234…`）、真实显示名 | 直接是个人信息 |
| 账户财务状态 | 积分余额、套餐档位、到期时刻、账单周期 | 与账号标识合并即构成可定位画像 |
| 本机路径 | `/Users/<姓名>/…`、`C:\Users\<姓名>\…`，以及用户主目录下的其它绝对路径 | 泄露操作系统用户名与目录结构 |
| 凭据库键名 | `~/.dsh/.credentials.yaml` 里的 `QODERCN_ACCOUNT_<id>` 之类 | 指向真实凭据条目 |
| 设备标识 | UMID、machineId、machineToken、序列号、`MachineGuid` | 设备可被唯一识别 |

> 注意：**`dingminhua` 与 `@dmh2002/` 这两个是公开身份**（GitHub 仓库地址、npm
> 包作用域、MIT 版权人），它们必须留在仓库里，脱敏规则不针对它们。要挡的是
> **它们之外**的账号数据。

## 2. 截图规则（本项目最容易出事的地方）

截图必须遵守以下四条，缺一条就算没过：

1. **先造数据，再截图。** 不要把真机界面遮一下发上来——遮的那一下常常遮不干净
   （见下条）。用 `scripts/*.preview.tsx` 那套假数据渲染，或者临时把账号名改成
   `acct-demo`、余额改成整数。
2. **遮挡必须是不透明的实心块或直接替换成假值。** **模糊 / 马赛克 / 半透明色块都不算**：
   模糊保留了字符宽度与字距，马赛克保留了亮暗分布，都能反推出「几个字、大概什么形状」；
   本项目 0.3.0 那两张 README 图用的就是模糊遮罩，1.19.2 一并换掉了。
3. **账号名、余额、到期时刻三者同框时，三项都要换成假值。** 只脱名字而把余额与
   到期时刻留着，等于给出一枚「可以对着时间线比对」的指纹——这正是 1.19.2 第一版
   修复的失手处：名字换了、数字原样留着，被独立审查当场判为不合格。
   余额与到期日的假值也要**看得出是假的**（`888`、`01/01/2027`），不要选一个
   碰巧像真的数字。
4. **截图前把窗口标题、侧边栏、浏览器标签一起看一遍**——它们常常带着另一个
   账号的名字。

**新增 / 重拍截图后必须做的事**：看一眼 `docs/assets/` 的实际像素，不要只看
Markdown 里的 alt 文字。alt 是写给读者的，不是写给你自己核对的。

## 3. 文字规则

- 记录「用户实拍」的现象时，用 `account-a` / `account-b` / `account-c` 代替真实昵称，
  用 `account-a@example.com` 代替真实邮箱。**保留现象，去掉身份**——「第 1 位的号
  已用尽却被排在最前」这句话本身是有效信息，只有名字需要换。
- 代码注释同样适用。`src/` 的注释会被打进 `lib/`，随 npm 包分发，等于公开。
- CHANGELOG 里的历史条目**不回改语义**，只做标识符替换；不要因为脱敏把当时的
  技术结论改掉。
- 日志、错误消息、`doctor` 输出已经统一走 `redactUpstreamText`（`src/probe.ts`）
  脱敏 `token=…` 一类的参数；新增日志路径时沿用同一个函数，不要自己拼字符串。

## 4. 提交前自检（30 秒）

```bash
# 1) 代码与文档里不该有的东西（与 tests/privacy.spec.ts 的规则一一对应）
grep -rnE 'nick[0-9]{7,}|@(msn|gmail|qq|163|126)\.com|pat-[0-9a-f]{16}|/Users/[A-Za-z0-9._-]+/|(?<!\d)1[3-9][0-9]{9}(?!\d)|"(machineId|machineToken|machineType)"\s*:\s*"' \
  --include='*.md' --include='*.ts' --include='*.tsx' --include='*.mjs' --include='*.json' \
  --include='*.yml' --include='*.reg' . | grep -v node_modules

# 2) 本次改动的图片，逐张打开看一眼（自动化查不了内容）
git diff --stat -- docs/assets

# 3) 自动化护栏（CI 也会跑，且是单独一步）
pnpm exec vitest run tests/privacy.spec.ts
```

> **护栏的能力边界，写清楚免得下次误信：**
> - 它扫的是**已知坏值的黑名单**，不是「未知好值的白名单」。新人名、新邮箱域、
>   新昵称形态一律漏——这次事故的主体（一个不是邮箱也不像昵称的显示名）它就抓不到。
> - 它**读不了图片内容**。截图只能靠人打开看。
> - 所以 §2 的第 1 条（先造数据再截图）才是治本的；护栏只防回退。

## 5. 已经泄露了怎么办

1. **先修当前 HEAD**：换图、替换标识符、`pnpm build`（让 `lib/` 里的注释跟着更新）。
2. **再判断要不要动历史**：只要旧 commit 还在，`git show <sha>:<path>` 就还能取出旧图。
   重写历史会改掉所有 commit hash、需要 force push、让所有 fork 失联，**不可逆**，
   必须维护者明确同意后才做；默认只修当前版本。
3. **已发布的 npm 版本撤不回来**：`npm unpublish` 只对 72 小时内、且没被依赖的版本
   生效。可行的是 `npm deprecate <pkg>@<ver> "含有已泄露的截图，请升级到 X.Y.Z"` +
   发一个修好的新版本。
4. **在 CHANGELOG 里写清楚**：哪一版漏了什么、修在哪一版。别悄悄换图——下一个
   维护者需要知道这张图为什么长得跟以前不一样。
